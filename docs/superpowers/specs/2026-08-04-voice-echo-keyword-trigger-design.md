# Voice Echo: Keyword-Triggered STT/TTS Dictation Echo

- **Date:** 2026-08-04
- **Rev 2:** 2026-08-06 — sherpa-onnx API/keywords format updated to current (1.13.x), gigaspeech English model pinned, piper voice reused from `~/.claude/piper-models/`, `/mute` flag integration added.
- **Status:** Design approved (rev 2)

## Summary

An always-on Windows program that listens on the microphone for the English
phrases **"hey computer listen"** and **"hey computer stop"** using a
sherpa-onnx zipformer keyword spotter.

- **"hey computer listen"** → enables live dictation (faster-whisper) and echoes
  each transcribed line aloud via piper TTS.
- **"hey computer stop"** → disables dictation and the echo, leaving only the
  keyword spotter running.

Fully local, offline, CPU-only, private.

## Goals

- **One always-on process.** The faster-whisper model stays loaded in memory
  for the whole run, so toggling is an instant flag flip — no per-toggle model
  reload (the reload would cost seconds each time).
- **Always-on keyword spotter.** Even while dictation is active, the spotter
  keeps listening so "hey computer stop" is always actionable.
- **Single microphone stream.** One `sounddevice.InputStream` feeds both the
  keyword spotter and the STT pipeline — no double-opening the mic.
- **Clean `ACTIVE`/`IDLE` state machine.** IDLE is silent and CPU-idle apart
  from the lightweight spotter.
- **Honors the voice-system mute flag.** `~/.claude/.voice-muted` (owned by the
  `/mute` and `/unmute` slash commands) is the canonical signal: while it
  exists, voice-echo speaks nothing and refuses to activate dictation.

## Non-goals (YAGNI)

- No `--type` clipboard-paste mode — that is whisper-live.py's job.
- No custom piper voice — English echo by default; a `--voice` flag exists so
  other voices can be supplied later.
- No Chinese trigger phrases in v1. The bilingual sherpa model
  (`sherpa-onnx-kws-zipformer-zh-en-3M-2025-12-20`) makes this possible later
  with zero retraining; swapping models is a config change, not a rewrite.
- No GUI / tray icon / autostart.

## Architecture

```
                 ┌────────────────────────────────────────────────┐
  mic ─► InputStream ─► dispatch ─┬─► sherpa-onnx keyword spotter (ALWAYS on)
 (16 kHz, 512-blk)│                 │  ┌─ "hey computer listen" ─► state=ACTIVE, speak "Listening"
                 │                 │  └─ "hey computer stop"  ─► state=IDLE,   speak "Stopped"
                 └─► when ACTIVE: silero VAD + ring buffer
                                     └─► faster-whisper transcriber thread
                                           └─► print "> text" + piper synth → sounddevice play
```

- One audio stream dispatches each block to the spotter and (when ACTIVE) the
  VAD/ring-buffer pipeline.
- The whisper model and piper voice are loaded once at startup and stay hot.
- Every path through the state machine re-checks the mute flag before any
  speech or state transition (see State machine).

## State machine

| Event | From → To | Actions |
|---|---|---|
| (startup) | — → `IDLE` | Load whisper model + piper voice; start spotter |
| "hey computer listen" | `IDLE` → `ACTIVE` | Speak "Listening"; prime VAD; begin transcription |
| "hey computer listen" | `IDLE` → `IDLE` | While muted: no-op (no speech, no activation) |
| "hey computer stop" | `ACTIVE` → `IDLE` | Halt transcription loop; drop queued/in-flight segments; speak "Stopped" |
| "hey computer stop" | `IDLE` → `IDLE` | No-op (spotter stays quiet) |
| mute flag set (mid-run) | `ACTIVE` → `IDLE` | Halt transcription immediately; drop queued/in-flight segments; no speech; spotter stays armed |
| Ctrl+C | any → exit | Clean shutdown; no audio |

## Behavior details

- **Echo:** each transcribed segment is spoken by piper. Raw PCM is
  synthesized in-process (`PiperVoice.synthesize_stream_raw`) and played via a
  `sounddevice` output stream — all-Python, no new playback dependency
  (no `ffplay`/`python -m piper` subprocess).
- **State cues:** "Listening" / "Stopped" are spoken aloud at each transition
  so the user gets audible confirmation the trigger registered — unless muted.
- **Mute semantics:** the mute flag is checked (a) before speaking any state
  cue or echo, and (b) before accepting "hey computer listen". While muted the
  state machine stays in `IDLE`; dictation is never activated and nothing is
  spoken. If the flag is created mid-dictation, in-flight and queued segments
  are dropped immediately and the state machine drops back to `IDLE` (the
  spotter stays armed). `hey computer stop` remains a no-op either way.
- **Mid-sentence stop:** if the spotter hears "hey computer stop" mid-sentence,
  the in-progress segment is discarded cleanly.
- **Noise-floor guard:** reuse whisper-live.py's guard (skip segments whose
  RMS < 0.01) so silence isn't transcribed.
- **Acoustic feedback (known limitation):** piper's own output may be picked
  up by the mic and either transcribed or (rarely) misheard as a phrase.
  Mitigations: headphones, or tune spotter thresholds. Acceptable for v1.
- **Errors** mirror whisper-live.py: bad mic → list available devices; model
  download failure → clear message; `Ctrl+C` → clean shutdown.

## Technical approach notes

### Keyword spotter (sherpa-onnx 1.13.x)

- **Install:** `pip install sherpa-onnx` (Windows `cp314` wheel exists for
  Python 3.14; verified against 1.13.4). This also installs the
  `sherpa-onnx-cli` console tool used to tokenize keywords.
- **Model:** download
  `https://github.com/k2-fsa/sherpa-onnx/releases/download/kws-models/sherpa-onnx-kws-zipformer-gigaspeech-3.3M-2024-01-01.tar.bz2`
  and extract into `C:\Users\admin\models\sherpa-kws\`. Trained on GigaSpeech
  XL (10k hours, English only). Ships `tokens.txt`, `bpe.model`,
  `encoder/decoder/joiner-epoch-12-avg-2-chunk-16-left-64*.onnx`, and
  `test_wavs/` for offline verification. Only the chunk-16 (320 ms latency)
  variants exist for this model.
- **API** (`python-api-examples/keyword-spotter-from-microphone.py`):

  ```python
  spotter = sherpa_onnx.KeywordSpotter(
      tokens=..., encoder=..., decoder=..., joiner=...,
      num_threads=1, keywords_file=".../keywords.txt",
      provider="cpu",
  )
  stream = spotter.create_stream()
  stream.accept_waveform(16000, samples)      # 16 kHz mono float32 blocks
  while spotter.is_ready(stream):
      spotter.decode_stream(stream)
      result = spotter.get_result(stream)
      if result:
          spotter.reset_stream(stream)         # mandatory after a detection
  ```

- **Keywords format (current):** one keyword per line of
  BPE-tokenized tokens separated by spaces, optionally followed by `:score`
  (boosting score; larger = easier to trigger) and `#threshold` (trigger
  probability; lower = easier to trigger). No spaces around `:` / `#`. Example:

  ```
  ▁HE Y ▁C O M P U T ER ▁L I S T E N :3.0 #0.25
  ▁HE Y ▁C O M P U T ER ▁S T O P :3.0 #0.25
  ```

  Generated from the human-readable `keywords.raw.txt` with:

  ```
  sherpa-onnx-cli text2token keywords.raw.txt keywords.txt \
      --tokens C:/Users/admin/models/sherpa-kws/sherpa-onnx-kws-zipformer-gigaspeech-3.3M-2024-01-01/tokens.txt \
      --tokens-type bpe \
      --bpe-model C:/Users/admin/models/sherpa-kws/sherpa-onnx-kws-zipformer-gigaspeech-3.3M-2024-01-01/bpe.model
  ```

  Do **not** hand-write the tokenized form; `text2token` owns it. Verify
  offline against the model's `test_wavs/` before the live mic test.

### Piper TTS

- **piper-tts 1.6.0** is already installed; the voice
  `en_US-lessac-medium` is already downloaded at
  `~/.claude/piper-models/en_US-lessac-medium.onnx` (used by the
  `piper-speak/speak.py` hook). Reuse it — do not download a second copy.
- **API:** `PiperVoice.load(model_path)` then
  `synthesize_stream_raw(text, sync=False)` → int16 PCM → `sounddevice`
  `OutputStream`.

### STT (faster-whisper)

- Reuse the proven pattern from whisper-live.py: silero-vad + ring buffer,
  `WARMUP` priming, `PAD_BEFORE`, `MAX_SEGMENT_SEC`, `MIN_SILENCE_MS`,
  `emit_segment`, and the noise-floor guard. Default model `small` (already
  cached by whisper-live usage); overridable with `--model`.

## Verification

1. **Offline:** run the spotter over the model's bundled `test_wavs/` using the
   bundled keywords to confirm the engine detects keywords at all, before any
   live mic work.
2. **Keyword file:** confirm `text2token` produces a valid `keywords.txt` for
   both trigger phrases (spotter starts without error; no "unknown token").
3. **Live mic test:** user says "hey computer listen" → hear "Listening", then
   dictate → lines echo aloud; say "hey computer stop" → hear "Stopped",
   dictation stops, spotter remains armed.
4. **Mute test:** run `/mute`, then "hey computer listen" → nothing spoken, no
   dictation; `/unmute` → trigger works again.
5. **Restart persistence:** voice-echo exits cleanly on Ctrl+C; no zombie
   processes; relaunch returns to `IDLE`.
